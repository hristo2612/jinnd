# Packet M1-P3 — Fiber Engine (`jinnd-fiber`)

**Milestone:** M1 · **Owner:** kernel-dev · **Status:** ready ·
**Binding rules:** R1, R2, R3, R5, R9, R10, R11 · **LOC budget:** 800–1200
(SOURCE-OF-TRUTH §6). Budget metric: src LOC excluding cfg(test), blanks, comments.

This is the R1/R2 crown packet: the lifecycle engine whose collapse disqualified
cordis-rs. Temporal semantics are the deliverable; structure is the easy part.

## Scope

Implement `crates/jinnd-fiber`: the lifecycle cell. One fiber = one instantiation
of one plugin; a plugin body runs once per fiber.

- **State machine** per the facade: `Pending / Loading / Active / Failed /
  Unloading / Disposed`. Committed-vs-target views (the paper's ten-rule
  calculus): the committed state is what has landed; the target is the latest
  desired state. Fiber uids as newtype u64, **never reused** (R3).
- **Per-fiber supervisor task** on tokio (R1): state published via a `watch`
  channel; in-flight setup carries a cooperative cancellation token. No
  `block_on`, no lock held across a call into plugin code — ever.
- **Single-flight inertia loop**: at most one in-flight transition per fiber; a
  launched transition ALWAYS lands, then reconciles to the latest target;
  intermediate targets coalesce (mid-flight changes never spawn a second
  transition and are never lost). This is the semantics the TS inertia-lock trio
  pins; those invariant cases stay verifier-owned — do not touch them.
- **Effect adoption**: each fiber owns a `jinnd-effects` scope. Loading registers
  effects through it; Unloading replays undos LIFO via the effects engine;
  `Disposed` is reached only after replay completes and reports. Failure
  mid-Loading unwinds exactly the effects registered so far (I1 seed).
- **Failure is local** (R11): a panicking/erroring plugin body or undo marks the
  fiber `Failed`, contained, with the outcome recorded. No auto-retry against an
  unchanged environment (R9).
- **Dependency readiness is abstracted**: the fiber consumes a readiness signal
  (small trait + `watch`-based source) that the registry packet will implement.
  NO service registry, NO epochs, NO event bus, NO loader in this crate — the
  seam is the deliverable, not the machinery behind it.
- **Loom**: model test(s) for the inertia loop's interleavings — launch vs
  target change vs cancellation — under `--features loom` (AGENTS.md requires
  loom for lifecycle concurrency; keep models bounded).
