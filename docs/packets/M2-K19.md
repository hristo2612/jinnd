**Design decisions in scope: ONE** — what happens to a stage file whose

## The observation

`crates/jinnd-daemon/tests/suspend.rs:265`,
`sigint_and_sigkill_agree_on_disk_and_sigint_flushes_the_suspension`:

```
left  (SIGKILL): [("log/a.txt", "one\ntwo\n"), ("log/b.txt.jinnd-stage", "bee")]
right (SIGINT):  [("log/a.txt", "one\ntwo\n")]
```

One file of difference: `log/b.txt.jinnd-stage`, the staging file of an
atomic write. `crates/jinnd-wasm/src/hostfs/retention.rs:98` does
`create(staged)` -> write -> fsync -> `rename(staged, target)`. SIGKILL
landed inside that window.

## The gap

`STAGE_SUFFIX` appears in exactly **two** places in the whole workspace: the
constant and the name builder. **Nothing sweeps an orphaned `.jinnd-stage`
file.** There is no boot-time cleanup, though `withdraw_orphaned_journals()`
shows the daemon already has the shape for one.

The orphan lands in the **guest's own directory**, beside its target. After a
crash a plugin sees a file it never wrote, and nothing ever removes it.

**I4: the quiescent state is indistinguishable from a fresh boot of the final
configuration; the mess leaves no trace.** A crash leaving permanent litter a
clean shutdown does not is a trace.

**COO reading: this violates I4. The verifier MUST challenge that reading
adversarially rather than adopt it.** If the reading is wrong, that finding is
worth more than the fix and the packet should stop there.

## Why it surfaced now, and why that is NOT the defect

The readiness gate is:

```rust
while read(data/log/a.txt) != Some("one\ntwo\n") || data/log/b.txt.exists()
```

`b.txt` is absent in **two** distinct states — "not yet staged" and "staged,
not yet renamed" — and the predicate cannot separate them, so it can return
mid-write. M2-K14 added boot work (`seed_net_effects` scans the ledger) and
M2-K17's `debuginfo=0` loads a smaller binary. Both shift timing; neither is
wrong. Any speedup widens the sampling window.

Exonerations, verified rather than asserted:
- `crates/jinnd-daemon/tests/suspend.rs` — untouched by K14.
- `crates/jinnd-wasm/src/hostfs/` — untouched by K14.
- The staging protocol is `b4b5554`, **M2-K8**, many packets earlier.

## Scope

1. **Sweep orphaned `.jinnd-stage` files at boot**, modelled on
   `withdraw_orphaned_journals()`. This makes the assertion true AS WRITTEN.
2. **Fix the readiness gate** so it distinguishes "not yet staged" from
   "staged, not yet renamed". Do BOTH — the gate alone silences the symptom
   and keeps the hole; the sweep alone leaves a nondeterministic test.
3. **RED-FIRST, and here the runtime repro IS the deliverable.** Force a crash
   inside the stage window; show the orphan surviving a reboot before the fix
   and removed after. A mechanistic argument was enough to FILE this; it is
   not enough to close it. This is the packet's one authorized local build —
   report disk before and after.
4. Sweep the workspace for other two-phase/suffix-staged writes with the same
   unswept-intermediate shape. **Report the count, including zero.**

## Explicitly prohibited

- Relaxing, retrying, or flaky-marking the assertion. It is defensible and
  currently false for a real reason; weakening it deletes the only pointer to
  the hole.
- Reverting `debuginfo=0` to make the test pass. That hides a defect behind a
  build flag and returns CI to 0.12 packets of disk headroom.
- Treating a green re-run as evidence. If it is a race, green is the majority
  outcome.
