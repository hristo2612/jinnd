## The defect

At pin `a53a352` every guest entry is one `settle(deadline, …)` on the
instance's own supervisor task (`crates/jinnd-wasm/src/instance.rs`,
`serve`; `crates/jinnd-wasm/src/settle.rs`), with `lane::DEADLINE` 5 s as
the deadline for every seat the lane instantiates. Fuel is set to
`u64::MAX` with a yield interval: it keeps a spinning guest cooperative
on the executor and caps nothing. `events.emit` is a host import that
runs INSIDE the emitter's guest call: `surfaces.rs` awaits
`LocalTopics::emit`, and `topics.rs` awaits every `target.deliver` end to
end, in every mode (`plugin.wit`, `events.emit`; M2-K10's fact 1). So a
listener's `handle-event` runs on the LISTENER's supervisor under the
listener's 5 s, while the emitter's supervisor keeps counting the
emitter's 5 s — and the emitter's clock started first.

Harness packet UI-2 (PLA-353), proof 7 of
`tests/composition/tests/moments.rs`, mounted a `while (true) {}` source
on `jinn:ui/before-send` and posted one moment through the transport,
whose emit runs inside the `jinn:net/readable` wake that carried the
request. FINDINGS #48, verbatim:

```
proof 7: the looping walk took 60.00011075s (guest deadline 5s); the moment's answer: None
  after the walk (listening, a bounded GET /v1/health as (elapsed, status), the transport's
  transitions): (true, (10.000736833s, None), [])  (before: incarnation Some(12))
  transport rows after the walk:
    191 ContractCall { contract: jinn:auth, operation: verify }
    192 AuthDecided { name: operator, granted: true }
    302 ErrorRecorded { error: { code: PluginFailed, message: "guest exceeded its call deadline", fiber: null } }
   1464 NetReadable { handle: 3 }
   1465 ErrorRecorded { error: { code: PluginFailed, message: "the instance is gone", fiber: null } }
  ext-looping rows after the walk:
    193 ContractCall { contract: jinn:clock, operation: now }
proof 7: THE TRANSPORT DIED ON THE WALK'S DEADLINE
```

Three defects, each its own line:

1. **The wrong clock.** The walk's cost lands on the emitter. At 5 s the
   emitter's `settle` fires first (its timer is older), the supervisor
   answers `Settled::Dead` and RETURNS: the transport's instance is gone.
   The emit future it was running is dropped with the call; the looping
   listener's own `Deliver` times out microseconds later and its reply
   goes to a oneshot nobody holds. Seq 302 was written by the `jinn:net`
   readiness wake path (`crates/jinnd-wasm/src/hostnet/readiness.rs`)
   recording a FAILED WAKE DELIVERY with the transport's attribution —
   the deliverer's row about the emitter, not a row about the listener.
   The listener wrote nothing.
2. **A dead instance is not a failed fiber.** `Settled::Dead` ends the
   supervisor task and tells nobody. The slot keeps the handle; every
   later command answers `gone()` (seq 1465). The fiber engine has no
   post-activation failure input at all — `Fiber` exposes `restart`,
   `suspend`, `dispose`, `owed` and nothing a body can call to say "my
   instance died" (`crates/jinnd-fiber/src/fiber.rs`) — so the transport's
   fiber shows NO transition, `jinn:introspect` reads `active`, and the
   operator API is down until the daemon restarts. R11 is broken in both
   halves: the wrong fiber died, and no fiber was recorded failing.
3. **A kernel-held registration outlives its instance.** The `jinn:net`
   listener is a `Registration::Kernel` in the seat's journal, released
   only by the seat's teardown — which never runs, because (2) never
   fails the fiber. The port keeps accepting (seq 1464) for an instance
   that cannot answer; the failure is invisible from the socket's side
   until a read is attempted.

## North-star fit

R11: a bad extension fails its own fiber and nothing else; here it
failed a sibling and no fiber. Law 2: model-visible means logged — an
instance death is the most model-visible fact a fiber has, and the only
row about it is another entry's delivery error. I1: a dead instance's
contribution (its socket) outlives it. I4: a daemon whose transport is
dead-but-`Active` is a state no fresh boot of the same profile produces.
R9: no auto-retry — a listener the kernel ended rests `Failed`, and
M2-K24 (c) re-arms it only when a declared provider moves. §1: the
kernel "never forgets what any tenant did" and is "legible" — the
operator API down with the record saying `active` is the opposite. The
UI-2 card withheld the `budget` field from the extension entry because
"a declared field the guest cannot enforce is a lie on the record"; this
card is what makes it honorable.

## The contract delta

**(a) Whose clock: the listener's, always.** Stated on `events.emit`: the
emitter's guest deadline DOES NOT RUN while the emitter is parked on a
walk. Each delivery is bounded on the listener's side — by the budget its
registration declared (b), or by the guest deadline when it declared none
— so the walk is bounded by construction: at most the sum of the selected
listeners' bounds, every one of them paid by the listener that set it.
A delivery that exceeds its bound ends the LISTENER's instance (c) and is
counted as one contained failure on the walk (R9): the walk continues,
the emitter is charged nothing, its own 5 s resumes when the walk
settles. Mode-independent — `emit` included, because the kernel awaits
every delivery (M2-K10 fact 1), so the parked span is the same in every
mode. Contract calls (`services.call`) are NOT covered (§Out).

**(b) A per-delivery budget, declared at `listen`, in fuel.** One
additive function beside `listen`:

```
listen-within: func(topic: string, token: u64, budget: delivery-budget)
  -> result<u64, kernel-error>;
record delivery-budget { fuel: u64 }
```

(names are the implementer's, declared in round 1). The unit is the
store's own fuel — the metering `consume_fuel` already runs — because
fuel is DETERMINISTIC: the same source exceeds the same budget at the
same instruction on every machine and under any load, which is what a
containment bound has to be (UI-2 §4.3's ten-boot determinism budget;
R9 — a wall-clock cap that trips under load and not otherwise is a retry
against an unchanged environment by another name). The bound is applied
per delivery: the supervisor sets the store's fuel to the budget before
`handle-event` and restores the cooperative setting after; exhaustion is
a trap, and a trap ends the instance (today's law, R11) → (c). The
guest deadline stays as the OUTER horizon of every delivery, budgeted or
not — a delivery parked on a host call burns no fuel, and the deadline is
what bounds that. Plain `listen` keeps today's bound (the deadline
alone); what changes for it is (a) and (c): whose clock, and what the
record says when it dies. A budget of zero is refused at `listen`,
`invalid`, on the record — a listener that can never be delivered to is a
declaration the kernel cannot honor. The budget is a property of the
REGISTRATION: it rides the journal through suspension, staging and the
Mode-1 `rebind` exactly as the token does (`Rebind` gains the field).

**(c) A dead instance fails its fiber, on the record.** Every
`Settled::Dead` a supervisor answers after activation — a deliver, a
handle-call, an undo, a restore, a trapped or hung `check` or `snapshot`
— becomes THREE things, in this order:

- one `ErrorRecorded { error }` attributed to the DEAD fiber (its own
  row, the fatal half of FINDINGS #51: "guest exceeded its call
  deadline", the trap, or the budget's message);
- a fault reported to the fiber engine through ONE new input, so the
  supervisor plans `Active → Unloading → Failed` under a new additive
  `TransitionCause` (working name `BodyFaulted`; the §Facade item). The
  doom is committed BEFORE the cleanup (the M2-K9 round-4 ordering law:
  a reader mid-cleanup already sees the truth);
- the seat retired through the journal it has: guest inverses answer
  `gone` and land `EffectWithdrawn { clean: false }` — honest, R6 —
  host-provider effects withdraw through the broker, kernel
  registrations release: the `jinn:net` listener closes (defect 3
  falls out; `NetClosed` on the record).

The fiber then RESTS `Failed` (R9); M2-K24 (c) re-arms it when a
declared provider moves and never before. A death that lands while the
fiber is already mid-transition (Unloading for a restart, or a disposal
in flight) is recorded once and reconciled by the engine's own landing
(single-flight inertia, R1) — exactly the interleaving the loom model
owes. The lane learns of a death from the instance itself: a death
notice on the handle, watched per instance the way `track_states`
already watches per fiber (`crates/jinnd-wasm/src/lane/state.rs`), never
by polling and never by waiting for the next command to answer `gone`.

**The ONE design decision — whose clock.** Three shapes were on the
table. (i) Shared, as today: #48. (ii) The emitter's REMAINING budget
bounds the walk, refused typed before any delivery when it cannot fit:
rejected — the kernel cannot know a delivery's duration in advance, so
the "refusal" is a guess, and an honest slow listener still kills the
emitter. (iii) The emitter's clock paused, every delivery bounded on the
listener's side: chosen — the pause is SAFE only because (b) and the
deadline bound every delivery, which is why (a) and (b) are one card and
not two. Recommended shape: `settle` takes a deadline the host imports
can EXTEND by the span they were parked (a resettable sleep on the
supervisor's task, fed from `HostState` around `topics.emit`) — no fiber
engine touch for (a). Rejected: spawning deliveries off the emitter's
task (the wait is the same wait, and the K10 wait-graph edges must still
cover it); a global per-walk deadline (the emitter is still the one
killed).

## Facade delta

**ONE item authorized:** `jinnd_api::TransitionCause` gains one additive
variant for a fiber failed by its own body after activation (working name
`BodyFaulted`), with a doc comment stating the contract. Nothing else:
the ledger vocabulary already has `ErrorRecorded`, `FiberTransition`,
`EffectWithdrawn`, `NetClosed`; the fiber engine's new input is a
`jinnd-fiber` API, not a facade one. A second facade item is a
STOP-and-escalate with the item named (the M2-K20 rule); an
unauthorized one is an automatic Blocker (two-key).

## Contract and profile-schema delta

`wit/plugin.wit` 0.10.0 → 0.11.0, additive (R12): `events.listen-within`
and `types.delivery-budget`; prose on `events.emit` (the clock rule, a);
prose on `lifecycle.handle-event` (a delivery runs under its
registration's budget; exhaustion ends the instance and fails the fiber,
on the record); `kernel-error.invalid` named for a zero budget. No
signature changes; every existing call means what it meant. The
contract-lens gate (M2-K16/K22) governs the bump. `jinn:introspect`:
NONE (an entry's `state` and its transitions already carry `failed` and
its cause; the registration's budget is not surfaced by this card — a
later minor if an operator surface needs it). Profile schema: NONE — the
budget is the GUEST's declaration at `listen`, not the entry's config
(R10: the extension tier's `budget` field, when the harness adds it, is
that plugin's config translated into `listen-within` by its provider).
Constitution: `docs/constitution/01-capability-contracts.md` §Grants is
untouched (a budget is containment, not authority); `02-ledger.md` gains
one sentence: an instance the kernel ends is a row on the fiber that
died.

## Invariant cases the verifier will own (named here, written by the verifier; each red first)

Homes are the verifier's call. What needs two real wasm guests and the
daemon is named so the fixture is built once; a looping guest and a
fuel-burning guest are the fixture's own controls.

1. `a_looping_listener_dies_on_its_own_slot_and_the_emitter_survives` —
   the #48 shape: one listener that never returns; the walk settles with
   `DispatchTrace { listeners: 1, failures: 1 }`; the emitter's fiber has
   NO transition and answers its next request within bound; the
   listener's fiber has `ErrorRecorded` under its own attribution, then
   `Active → Unloading → Failed` under the new cause; siblings untouched
   (R11); no deadline row on the emitter.
2. `a_delivery_over_its_declared_fuel_budget_ends_deterministically` —
   `listen-within` with budget N; a delivery that burns more than N
   traps at the same point on every run (k runs, identical rows), in
   wall time far under the deadline; the walk's other listeners still
   ran (R9: contained, never aborted); the fiber failed as in case 1.
3. `the_emitter_is_charged_nothing_for_a_walk` — selected listeners
   whose deliveries SUM past 5 s, each under its own bound; the emitter's
   own work under its deadline; the walk completes, `failures: 0`, no
   deadline row anywhere; the emitter's 5 s demonstrably resumes after
   the walk (a post-walk spin dies at the deadline, on the emitter).
4. `a_dead_instance_releases_its_kernel_registrations` — defect 3: a
   listener holding a `jinn:net` listener dies on a delivery; its port
   stops accepting; `NetClosed` after the `Failed` row; guest inverses
   land `EffectWithdrawn { clean: false }`; host-provider effects
   withdraw clean.
5. `an_unbudgeted_listen_is_unchanged_in_bound` — the ratchet: plain
   `listen`; a 4 s delivery completes as at `a53a352`; a 6 s delivery
   dies at 5 s ON THE LISTENER (row + `Failed`), the emitter alive.
6. `a_failed_listener_is_not_retried_and_re_arms_only_when_declared_input_moves`
   — R9 with M2-K24 (c): `Failed` stays across an unrelated sibling's
   restart; a declared provider's generation change re-arms it once.
7. `a_zero_budget_is_refused_at_listen_on_the_record` — `invalid`,
   `ErrorRecorded` with the listener's attribution; the entry's other
   registrations stand; siblings unaffected.
8. `a_death_during_an_in_flight_transition_lands_exactly_once` — the
   fault reported while the fiber is `Unloading` for a `ConfigChanged`
   restart, and again while a disposal is in flight: exactly one terminal
   state each, no double withdrawal, no lost fault, no `Failed` after
   `Disposed` (the implementer's loom model covers the interleavings;
   the verifier's case pins the observable on the record).

## Round protocol — 2 rounds

- **Round 1 (build):** red-first in the crates' own test modules, one
  failing test per behaviour (a), (b), (c) in its own commit before its
  implementation; the loom model for (c); the meter declared before
  code; `wit/plugin.wit` bumped with the lens gate green. The verifier's
  round-1 verify runs the crate suites and the standing gates on the
  packet head and files findings by rule.
- **Round 2 (answer):** findings answered with evidence; the verifier's
  cases run from `invariants/m2-k25` in the verify node's own checkout on
  the packet head; `pass` = 0 Blockers.
- **STOP RULE:** 2 rounds; a third is the COO's call, on evidence. If (c)
  cannot be built with ONE fiber-engine input, or (a) cannot be built
  without a second facade item, STOP and escalate with the loom model and
  the item priced — a scoping ruling is the COO's.

## Invariants lane — the two-key rule, stated

Verifier-owned cases land on **`invariants/m2-k25`**, a verifier-lane
branch, as a separate PR AFTER the implementation lands — never on the
packet branch. The repo enforces it: `.github/scripts/check-push-two-key.sh`
refuses a push touching both `tests/invariants/` and implementation
crates without an independent verifier author, and every implementer
session here commits under one identity. The verify node runs the cases
from `invariants/m2-k25` inside its own checkout on the packet head; after
the implementation merges, the verifier fast-forwards the lane onto
`main` and pushes it as its own invariants-only push (label
`verifier-approved`). A merge-conflict resolution touching
`tests/invariants/` takes the verifier's side byte-for-byte or STOPs
(AGENTS.md). The CI check is never weakened.

## Rules cited

R1 (the paused clock is a resettable sleep on the supervisor's own task;
a death notice is a watch, never a poll; no lock across guest code), R3
(the budget is a typed record; the death is a typed cause, not a
sentence), R5 (nothing here mutates outside the journal; the retire is
the journal's own replay), R9 (a killed listener rests `Failed`; a
nondeterministic cap would be a retry by another name), R10 (one
function, one record, one cause, one input; no per-entry config; no
introspect change), R11 (both halves restored: the failing plugin's OWN
fiber fails, and it is the only one that does), R12 (additive minor;
nothing existing changes meaning), Laws 1/2 (containment declared by the
guest at the contract, enforced by the kernel; every death a row on the
fiber that died), I1/I3/I4 as named above.

## Explicitly OUT

- **A budget for `services.call`.** A provider's slow answer still spends
  the CALLER's clock (FINDINGS #4/#32's class; M2-K10 refused the cycle,
  not the wait). Later card; the pause mechanism in (a) is to be built
  so that card can reuse it.
- **A per-entry default budget in the profile**, or any kernel-side
  default other than the deadline: the extension tier's business (R10).
- **#51's non-fatal `DeliveryFailed` row** — a listener's CONTAINED
  failure stays a count on the emitter's trace; only the fatal case
  lands on the listener here.
- **#50's memory reading** on `jinn:introspect`.
- **Cumulative fuel accounting** across deliveries or per incarnation.
- **Any change to the M2-K9/K10 refusals, the wait graph, or the topic
  table's selection**; the restart window is M2-K26's.
- **Harness-side changes**: the pin-bump is its own packet.
