## Scope

### `crates/jinnd-loader`
- **Profile document = entry tree** (LAW §3): serde-typed at the contract
  boundary (R3) — a tree of plugin entries with stable ids, per-entry config
  payloads, and grouping/isolation directives. Realms per the audit doc: local
  (`#entryId`) and global (`@label`) isolation directives map onto the context
  crate's realm machinery.
- **Reconcile by id**: diff current tree → desired tree; produce a minimal plan
  (create / update-config / restart / dispose); ONLY affected fibers restart —
  siblings untouched (I1/I4 seeds; uses registry epochs + the fiber engine's
  target calculus through the kernel surface).
- **Bidirectional persistence**: runtime changes write back to the document
  ATOMICALLY (write-temp + rename; no partial states on disk). The running
  system and the config document are two views of one truth. v0.1 constitution
  bounds: local-only profiles; no destructive compaction.
- **R9, mechanically dead**: config is DATA — no expression evaluation with
  ambient authority of any kind in v0.1 (no interpolation that reads env/fs, no
  code in config). A malformed document is a contained per-entry failure (R11):
  good entries load, bad entries surface recorded errors, nothing panics.
- **Pure-core discipline**: the crate takes a document and a kernel handle —
  parse + diff + plan + apply. File-watching and the fs host-provider contract
  are NOT this packet; the daemon wires them later (the seam is the deliverable).
- **Async-first** (R1): apply drives kernel operations without holding locks
  across them; plan application is cancellable between steps.

### `crates/jinnd-adapter` wiring
- Wire the loader subsystem: load/reconcile/write-back through the adapter's
  kernel. The 38 `NO_KERNEL: loader` cases become executable; remaining
  subsystem stubs keep their exact reason strings.
