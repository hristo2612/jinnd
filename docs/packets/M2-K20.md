## The observation

`crates/jinnd-wasm/src/hostnet/tests.rs:626`, in a final-head
`cargo test --workspace --no-fail-fast` run during M2-K19 round 2:

```
a_flood_wakes_once_and_a_released_socket_never_wakes_again ... FAILED: "closed at release"
```

The tail listed **10 failed targets** including `-p jinnd-wasm --lib`, where
only the 9 catalogued `jinnd-invariants` targets are accepted. Immediate exact
and crate-level reruns were **green**. The verifier reported the failure rather
than letting the reruns erase it and named the reruns as *demonstrating
nondeterminism*, not as evidence of health. That handling is the standard: a
rerun cannot un-fail a gate.

## Why this is priority 1

This is M2-K14's code and it is already on `main`. A nondeterministic failure
in outbound-socket wake logic is not a test-hygiene issue until proven to be
one — the reasoning that turned M2-K19 from "bad test" into a real I4 gap. The
test may be right and the wake logic may race.

It also blocks confidence in every future packet's workspace gate: while this
fires intermittently, any non-catalogued red is ambiguous between "new defect"
and "the known flake", which is exactly the condition M2-K12 exists to prevent.
M2-K19 and M2-K21 both carried it as a named exception; that exception expires
when this packet closes.

## Scope — one design decision: is the wake contract or the test wrong?

1. **Reproduce deterministically.** A frequency estimate is not a diagnosis.
   Force the interleaving — the M2-K19 precedent is the standard: a real
   window forced open beats a repro rate. **Independence matters:** N runs
   launched in one window are one draw wearing N faces; state what differed
   between runs for them to count as independent.
2. **Decide which is wrong, and say so explicitly:**
   - the **wake logic** has a race — a live defect in shipped kernel code; the
     fix is the kernel's, proven RED-FIRST against the deterministic repro; or
   - the **test** encodes a timing assumption rather than the invariant it
     names — the replacement asserts the actual property, never a relaxed or
     retried version of it.
3. **State plainly whether a plugin could observe this in production**, and
   under what conditions. "Only under test load" is acceptable **if
   demonstrated**, not if assumed.

## Prohibited

- Retry wrappers, `#[ignore]`, flaky-marking, relaxed assertions, or a
  sleep that widens a window. If the test is wrong, replace it with one that
  is right; do not silence it.
- Treating green reruns as evidence of absence. Green is the majority outcome
  of a race.
- Preserve failure evidence BEFORE re-running anything: a re-run replaces the
  default log view.

## THREAT MODEL

Ordinary concurrent socket use under load. Not an adversary timing calls.

## Evidence standard — inherited, not restated

Checkable red-first (failing test in its own commit, or verbatim output).
Mutation-verified coverage: **for each mutation, the file:line changed, the
exact command, and the verbatim failing output, posted as a Todo comment.**
Contract text, if touched, asserted by PARSING, never `contains`. The full
`cargo test --workspace --no-fail-fast` at final head shows exactly the 9
catalogued invariant targets failing and no others, across at least two
independent runs separated in time — name the separation.

`pass` = 0 Blockers; a behaviour-free Major is named in the verdict and fixed
before land. The repo is PUBLIC: zero personal data or machine paths in any
push.

STOP RULE: 3 rounds. If the race cannot be reproduced deterministically, that
is itself the finding — report the exact conditions tried, with the
independence of each stated, and do not close as "could not reproduce"
without them.

## COO ruling — 2026-09-02, after round 1 (binding)

Round 1 decided the question the card asked — **the wake contract is right,
the test was wrong** — with a deterministic in-tree repro on every platform,
zero production lines, mutation evidence in form, and green gates on both
platforms. It came back `rework` on ONE Blocker: the implementer's declared
production meter (`0 LOC`, spelled as a `git diff --numstat` with three
exclusion patterns) prints two lines — the `#[cfg(test)] mod release_tests;`
registration in `hostnet.rs:43-44`.

**Ruling: the number is 0.** SOURCE-OF-TRUTH R10's metric note excludes
`cfg(test)` code as a CATEGORY; a declaration's spelling of the meter never
narrows what the law excludes (the M2-K15 round-3 ruling, applied identically
here). A `#[cfg(test)]` attribute and the `mod` line it governs are cfg(test)
code and are outside a production budget, whatever pattern list a
declaration happened to use. The verifier was right on the letter of the
declaration and the letter was defective — the FOURTH instance in this
program of a meter naming a category and being spelled as a pattern that
misses it (K15 ×3, K20). That is M2-K18's whole reason to exist; until K18
lands, this paragraph is the standing rule.

**Round 2 is a CONFIRM round, not a rework:** no code change is required or
wanted. The implementer corrects the Minor (the test-meter arithmetic reads
180 added / 27 removed, not 179) in a Todo comment and submits the same head
`dae5c48`; the verifier confirms the head, the ruling and the Minor, and
passes. Churning the branch to satisfy a defective pattern is prohibited.
