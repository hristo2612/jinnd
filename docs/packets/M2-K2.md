## Finding 1 → `jinn:clock` (FINDINGS.md #1)

Guests are purely reactive; time cannot honestly enter the system. The
harness ships a config-rewrite tick workaround costing ~5 ledger rows of
fiber churn per tick. Retire it:

- **Contract bundle `jinn:clock`** (constitution-01 format, versioned): `now`
  (a read — granted, no effect registration needed beyond the call ledger
  line) and an **alarm surface**: request a wake at instant T or every period
  P; delivery as a typed `handle-event` payload to the requesting plugin;
  cancellation via the standard effect undo (an alarm request IS an effect —
  R5 — its undo cancels the alarm).
- **Kernel-side emitter**: host-owned timer machinery (tokio time in the
  production host — R1: no lock across guest delivery; alarms survive
  hot-swap via the seat's staged outcome like any effect; alarms do NOT
  survive daemon restart in v0.1 — plugins re-request on activate, document
  this honestly in the contract).
- **Every wake is a ledger event** (Law 2) with the requesting entry/fiber
  attribution. Grants scope alarm resolution (a profile may cap how fine a
  timer an entry may hold — R9: no free high-frequency wake hazard; document
  the default cap).

## Finding 2 → `DispatchTrace` tap (FINDINGS.md #2, M1-P7 reserved debt)

Bus emits are invisible to Law 2 — a cron FIRE leaves no direct ledger
event. Wire the reserved class:

- One `DispatchTrace` ledger event per bus emit: topic, dispatch mode,
  listener count, contained-failure count, emitter attribution. For cron this
  line IS the audit statement "job X fired at T".
- Tracing must not hold any lock across listener execution (R1) and must not
  change dispatch semantics — append is fire-and-forget relative to the walk;
  a ledger append failure is recorded via the ledger's own honesty path,
  never propagated into dispatch outcomes (R11).
- Volume note: bus emits are contract-level events, not data-plane traffic —
  this is within the R7 ledger-granularity ruling. No sampling/filtering in
  v0.1; if the soak shows volume pain, that is a new finding, not a silent
  toggle.

## Acceptance

- A fixture plugin requests a periodic alarm and receives typed wakes through
  the real daemon; every wake ledgered with attribution; undo cancels; grants
  cap resolution; hot-swap preserves live alarms via the seat outcome;
  restart drops them and the contract says so.
- Every bus emit through the daemon path lands exactly one DispatchTrace with
  correct topic/mode/counts; dispatch behavior byte-identical otherwise
  (existing suites green unchanged).
- Ratchet: no regressions (95/35 baseline; growth only via verifier
  adjudication); gates + loom (timer/seat interleavings) + miri (non-FFI) +
  `--locked`; two-key clean; ceilings per this card.
- The contract bundle is additive and versioned (R12); harness pin-bump is
  NOT this packet (the harness adopts via its own pin-bump procedure after
  land).
