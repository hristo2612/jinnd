## What M2-K14 left

`jinn:net` 0.2.0 provides `request` and `send-request` behind the profile
allowlist, declared irreversible, with the refusal surviving a daemon reopen
and both entry doors proven. **All of it is loopback-only.** No TLS means no
Slack, no Stripe, no Linear, no GitHub, no vendor engine API — the M3
acceptance ("an instance runs a full day on jinnd alone") is still blocked,
just for a narrower reason than before.

This card was deliberately split out so it would carry **exactly one design
decision**. Do not widen it.

## The decision, and how to justify it

Pick a TLS stack and defend it under R10 ("small and boring"). State the
alternatives you rejected and why. The axes that matter here, in order:

1. **Supply-chain surface.** Count the transitive dependencies each option
   adds and say the number. This is a kernel that has kept its dependency
   list deliberately short.
2. **Certificate verification and where the trust roots come from.** Platform
   store versus a vendored root bundle is a real choice with real
   consequences; name which and why.
3. **Build cost.** M2-K17 measured CI headroom at ~29 packets of margin, and
   a TLS stack is a large compile. Report what it costs. **The unstacked
   `reclaim runner disk` step in `test-inventory` is worth ~+18 GiB on the
   free tier** — it exists and is available if this packet needs it; use it
   deliberately and say so, do not discover it.
4. Whether it can be a plugin rather than kernel code. R10 says anything that
   can be a plugin is a plugin. If the answer is no, say why in one paragraph.

## What must hold, beyond "https works"

- **Certificate verification is ON and cannot be silently disabled.** No
  `danger_accept_invalid_certs` path reachable from a profile, an env var, or
  a plugin. If a test needs a self-signed cert, it gets one through an
  explicit, test-only seam that cannot exist in a release build — and prove
  that with a test asserting the seam is absent, not by inspection.
- **A bad certificate is a TYPED refusal**, distinct from an off-allowlist
  refusal and distinct from a transport failure. Three different answers, each
  asserting its own precondition.
- **The allowlist still binds over TLS**, including on redirect. M2-K14 proved
  a redirect to an off-allowlist authority is refused inside the host call;
  prove it still holds when the hop is https.
- **Both doors again.** `request` and `send-request` enter one `outbound()`
  core. Every property above must be proven through **each**, table-driven —
  the M2-K14 precedent, where the legacy door's guarantees were asserted by
  construction and a mutation showed the old suite caught the allowlist hole
  with exactly one assertion and the redirect hole with none.
- **Irreversibility is unchanged.** A TLS request is still `irreversible`,
  still ledgered with the redacted row shape, still refused by `revert_unit`
  after a reopen. Re-prove it over TLS rather than assuming K14 covers it.
- **No credential leaks into the ledger row or into an error message.** K14
  proved it for the header; prove it for whatever TLS adds (SNI, cert
  subjects) if anything.

## Evidence standard, carried from the packets before this one

- **Red-first must be checkable.** The failing test in its own earlier commit,
  or verbatim failing output in the report. An unprovable red-first claim is
  worth less than none.
- **A test that passes on first run proves nothing.** Mutation-verify: break
  the guarded behaviour deliberately and show the new tests fail while the old
  ones pass.
- **Assert contract text by PARSING, never by `contains`.** The `toml`
  dev-dependency added in M2-K19 is the precedent. Five instances of the
  unanchored-substring vacuity have shipped in this program; do not make it
  six.
- **Identical signature is not identical observation.** Report what was seen,
  where, and say plainly where inference begins.

## Named exception, inherited from M2-K19

`a_flood_wakes_once_and_a_released_socket_never_wakes_again`
(`hostnet/tests.rs:626`) fails nondeterministically and is owned by
**PLA-340 / M2-K20**. If the ONLY non-catalogued failure at final head is that
test, cite M2-K20 and proceed. Any other non-catalogued failure is a blocker.
This exception expires when M2-K20 closes.

THREAT MODEL: an ordinary hostile or misconfigured network peer — expired,
self-signed, wrong-host, or downgraded certificates. Not a state-level
adversary with a trusted-root compromise.

STOP RULE: 3 rounds. If the TLS stack choice itself is contested, that is an
escalation to the COO, not an implementation problem.

> **WHAT A MAJOR DOES (COO ruling, 2026-09-01, binding from here).**
> `pass` = **0 Blockers**. A Major is recorded and MUST be fixed, but a Major
> that is **provably behaviour-free** — comments, formatting, naming, divider
> ASCII — does NOT by itself justify a fresh adversarial round. Report `pass`,
> name the Major, and the implementer fixes it before land; the verifier
> confirms that single hunk rather than re-reviewing the packet.
>
> A Major touching **behaviour, evidence, or a safety boundary** keeps its full
> force and still returns `rework`.
>
> Occasion: round 2 had 0 Blockers and 1 Major — two `// -----` divider lines —
> and spent an implement node, a full adversarial re-verify and a round of the
> stop rule on them. The finding was right; the cost of the response was not.
> Distinguishing "must be fixed" from "must be re-adjudicated by a full
> adversarial pass" is the COO's job, and it had not been done. This is NOT a
> softening of Jinn Taste §1.
