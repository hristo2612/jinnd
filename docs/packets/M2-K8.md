## Scope

### #5 remainder → live `jinn:keystore` provider behind its existing bundle
- Register the provider like the other base providers: `get(key)`,
  `put(key, value)` (revertible per the bundle: inverse restores the prior
  value or absence; the inverse itself is stored in the retention store
  ENCRYPTED, never plaintext on disk — see below), `delete(key)`, `list()`
  (names only). Backing store in v0.1: the platform keychain where available
  (macOS Security framework via the existing R10-justified dependency
  policy — a new dependency needs a one-line justification in Cargo.toml),
  else an encrypted file under the data root with a key derived from an
  operator-provided passphrase or platform secret; document the honest
  security boundary in the bundle README.
- **Ledger discipline (Law 2 + sensitivity):** every keystore call is a
  ledgered contract call; payloads carry the KEY NAME and a value digest
  only — never the value. The `jinn:ledger` reader's redaction class
  already covers this; extend it if the payload shape needs it.
- **Grants:** scope = key-name prefix allowlist, fail-closed per the K2 law;
  read-only attenuation available (see #24) so a consumer that only reads
  cannot write.

### #22 → atomic `jinn:fs` writes
- `write` and `append`'s underlying commit become stage + fsync + rename
  (reuse the retention store's helper); a concurrent reader never sees a
  torn document. Red-first: a reader racing a large write observes either
  the old or the new document, never a prefix.

### #24 → operation-class attenuation on `jinn:fs` grants
- A grant scope may declare `ops: [read, list, meta]` (default: all ops when
  absent — additive, R12); a write/append/remove under a read-only grant
  REFUSES (typed, ledgered). Same mechanism for `jinn:keystore`
  (`ops: [get, list]`). Red-first per refused op.

### #26 → non-blocking `jinn:profile.patch-entry` (added 2026-08-29, C5/C6 decision)
- `patch-entry` answers `accepted { seq }` as soon as the document is
  committed (atomic write-back) and the patched fiber's restart is
  SCHEDULED — it never awaits the restart inside the caller's host call.
  The restart's outcome is observable afterwards through the ledger
  (`ProfilePatched` then the fiber transitions) and `jinn:introspect`. This
  removes the two-hop nested-dispatch deadlock (settings provider patches its
  owner; the owner's `activate` calls the provider) — the Algorithm-5
  deferred-amendment shape from the 2026-08-25 ruling. The self-patch refusal
  stays. Red-first: the harness's two-hop shape (owner resolves settings in
  `activate` while its provider is mid-`patch`) completes without hitting
  the guest deadline. Ceiling for this item rides inside the card total
  (re-priced below).

### #25 → read-only document view (added 2026-08-29)
- `jinn:profile` gains `entry(id)` / `document()` reads (granted read-only —
  the #24 attenuation applies), returning the document's authority fields
  (`package`, `hash`, `grants`, config) so viewers need no `jinn:fs` scope on
  the profile and the profile may sit anywhere. Ledgered per read.

**COO round-1 rulings (2026-08-29):** (a) the vault master key is NEVER
stored beside the ciphertext — macOS: platform keychain via a crate
(R10-justified in Cargo.toml; the `security` CLI through jinn:process is not
acceptable for the kernel's own vault); elsewhere: a key derived (argon2id /
scrypt) from an operator-provided passphrase or platform secret supplied
outside the data root; red-first: the data root alone cannot decrypt.
(b) Grants of one contract to one entry compose order-independently: scopes
union, effective ops = union of each grant's declared ops (absent = all);
attenuation narrows within a grant only. (c) Effect identity in teardown and
journals is (contract, effect id) everywhere. (d) Ceiling ≤1950 by the
canonical meter (round-1 measured 1651; rulings add ~250). (e) The 300-line
cap is hard for src, soft for coherent test suites — new test files over the
cap are split where a natural seam exists, never a blocker alone.

**COO round-2 adjudication (2026-08-29), binding:**
- **Canonical meter, test exclusion defined.** "Excluding test modules" means
  every file under a `tests/` directory OR named `tests.rs`, on both sides of
  the numstat — the mandated suite split must never inflate the production
  meter. Measured under that definition, round 2 is 1964.
- **Ceiling re-priced ≤2100** (round-2 measured 1964; the bind-set fix below
  adds ~60). The implementer does NOT golf to fit; escalate with a breakdown
  if the honest implementation exceeds it. The 1950 figure is superseded.
- **Ruling (b) is EXACT UNION; the bind HULL is REJECTED.** A hull over
  `[1000,1000] ∪ [2000,2000]` admits port 1500, which no grant conferred —
  authority widening, Law 1. `GrantScope.bind` becomes a SET of ranges
  (normalized: sorted, overlapping/adjacent ranges coalesced, so equal sets
  compare equal and composition stays order-independent); the listen check
  admits a port iff SOME range contains it. Red-first: two disjoint
  single-port grants compose, and a bind to a port between them REFUSES with
  `ScopeMismatch`. This supersedes any earlier acceptance of the hull.
- **A configured secret source that cannot be read FAILS CLOSED.** If
  `JINND_KEYSTORE_PASSPHRASE_FILE` is set but unreadable (missing, permission
  denied, empty), `open` returns a typed error naming the source — it never
  degrades to `Absent` or to another backend. Red-first per failure mode.
- **The macOS keychain backend stays compiled-but-untested** (the login
  keychain would prompt); the passphrase backend is the tested and documented
  headless choice. Not a finding.

## Round protocol
Standard kernel-packet rounds; verifier owns invariant additions
(candidates: keystore-value-never-in-ledger; read-only-grant-refuses-write;
write-is-atomic; patch-entry-never-awaits-restart). Hostile probes: value leaks via error text or ledger

## Acceptance
- Fixture through the real daemon: put/get/delete/list under a prefix grant;
  the ledger shows key names + digests only (verifier greps the ledger file
  for the value bytes: zero hits); a read-only keystore grant refuses put;
  a read-only fs grant refuses write/append/remove; a torn-read race on a
  large document never yields a prefix.
- Ratchet: no regressions (95/35); gates + loom + miri (non-FFI) +
  `--locked`; two-key clean; ceilings per this card; 300-line cap.
- Contract deltas additive and versioned (R12). Harness adopts via pin-bump
  7 (the settings seam's secret references resolve; engines can hold keys).
