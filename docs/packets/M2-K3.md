## Finding 3 → finalize `jinn:fs` to its declared bundle (FINDINGS.md #3)

The contract bundle declares `list`, `read`, `write`, `remove` (+ `file-meta`
with `modified-ms`), but the plugin world's `fs` import and HostFs answer only
`read` and `write`. Consequences measured in the harness: the health snapshot
cannot enumerate or stat anything; the scheduler's run history is a full-file
rewrite per fire (O(n) per append). Close the gap:

- **`list` and `file-meta`** — reads (call-ledger line, no effect
  registration), scoped by the entry's grant like every other op. `file-meta`
  carries at least `modified-ms` and size. Reads of a missing path return a
  **typed not-found** (the harness had to classify absence by folding a
  generic error — that ends here).
- **`remove`** — an effect (R5): revertible, inverse restores the prior
  content through the same retention store as `write` inverses.
- **`append`** — new operation, additive to the bundle (R12: versioned
  edition): effect with inverse = truncate-to-prior-length. This is the
  natural shape for guest-kept logs and retires the harness's O(n)
  rewrite-per-fire pattern.
- **Grant discipline unchanged and fail-closed** (M2-K2's admission law): the
  new ops enforce the same scoped grants; each new op refused without a grant
  is a pinned red-first test; the K2 wrong-type-scope probe must stay green as
  a regression.

## Finding 8 → HostFs effect-retention policy (FINDINGS.md #8)

Every write effect's prior content lives in the provider's RAM forever (the
`hostfs.rs` undos map — no compaction, no spill). The live soak measures the
curve: ~4 effects per fire, a week of 15-minute duty ≈ 2,700 retained
prior-contents, monotonic. Fine for a demo, wrong for a daemon:

- **Inverses spill to a durable store** under the daemon's data root, keyed by
  effect id; the in-memory map becomes bounded. The inverse is persisted
  BEFORE the mutation commits — if the inverse cannot be made durable, the
  effect is REFUSED with a ledgered per-entry error (fail-closed: the
  revertibility guarantee is never silently weakened; same doctrine as K2's
  grant admission).
- **Withdrawal/undo consumes the spilled inverse and reclaims its storage**;
  dispose leaves no orphaned inverse files for that fiber's trail (LIFO replay
  through the effects engine unchanged — R5, M1-P9b law).
- **Memory bound is testable**: driving N write effects must not retain N
  prior-contents in provider memory, with inverses still functional from the
  spill store. No timer/compaction daemon — retention is event-driven
  (register/withdraw/dispose), R10.

## Acceptance

- A fixture plugin exercises list/meta/remove/append through the real daemon
  under scoped grants: undo of append truncates to prior length; undo of
  remove restores prior content; every op ledgered with attribution; missing
  paths yield the typed not-found.
- Red-first: each new op without a grant refuses (ledgered); K2's wrong-type
  scope probe green as regression; inverse-not-durable refuses the effect.
- Retention: bounded-memory test green (N effects, provider memory does not
  grow O(N) in prior-contents; undo from spill works; withdrawal reclaims;
  dispose leaves no orphans).
- Ratchet: no regressions (95/35 baseline; growth only via verifier
  adjudication); gates + loom + miri (non-FFI) + `--locked`; two-key clean;
  ceilings per this card; src files under the 300-line cap.
- The contract bundle change is additive and versioned (R12); harness
  pin-bump is NOT this packet (the harness adopts via its own pin-bump
  procedure after land).
