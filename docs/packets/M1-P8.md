## Scope

### WIT contracts (constitution 01 — the product, R12)
- Author the v0.1 WIT interface files under `wit/`: the plugin world (lifecycle
  entry points, effect registration, service provide/inject, event
  emit/listen, config surface) and the base host-provider contracts as
  IMPORTS the kernel supplies. Contracts are versioned; prose law from
  constitution 01 travels as doc comments. These files outlive the
  implementation — design them as such.

### `crates/jinnd-wasm` — Tier A host + transport-agnostic broker
- **The broker is the single dispatch point** (decision log 2026-08-25, binding):
  grant check → ledger append (R6) → dispatch, accepting "a contract call from a
  peer". The peer being a linked WASM instance is a TRANSPORT detail behind a
  seam; a broker fused to wasmtime linking is a design defect. The conformance
  harness lane routes through THIS SAME broker (test-harness ruling closure c).
- **Tier A hosting** (R7): load a `.wasm` component pinned by content hash
  (constitution v0.1: pin-by-hash; a mismatched hash refuses to load — Law 5's
  provenance floor for M1; full signature envelopes are post-M1), instantiate
  per fiber, wire the plugin world to kernel surfaces via the broker, dispose
  instantly and completely on fiber teardown (I1: instance drop withdraws
  exactly its contribution).
- **Harness-lane closure** (test-harness ruling, acceptance a+b): the production
  plugin path is WIT/broker ONLY; the in-proc `jinnd-api::Kernel` facade lane is
  compile-gated OUT of any daemon/production build target (feature-gate it;
  prove with a build of the production feature set that does not contain it).
- **R8 Mode-1 hot-swap with rollback** (the M1 demo requires this): swap a
  component instance for a new artifact — old instance stays warm until the new
  one reports healthy, auto-rollback on failure, optional state-handoff blob old
  → new. Swap batches ALL entries sharing an artifact hash (cordis
  Runtime-roster analog, decision-log item). Every swap phase is a ledger event.
- **Per-consumer vitality-check seam** (C3, binding): provider checks are
  evaluated per consumer, per notify — the seam shape must be expressible over
  the broker (a WASM provider answers a check call), replacing the vacuous
  provider-side bool.
- **Declarative event selectors** (C4, binding): the WIT event contract carries
  a declarative selector (all / by-context-set / by-realm-of(service-name));
  closures never cross the boundary; realm queries evaluate kernel-side.
- **Containment** (R11, Law 5): a trapping/hanging guest deactivates its own
  fiber cleanly — traps are contained per fiber, recorded, never cross the
  kernel boundary; epoch-deadline or fuel yields keep a spinning guest from
  starving the executor (R1: no kernel lock held across guest execution, ever).

### `crates/jinnd-adapter` wiring
- Wire a wasm-backed package lane through the kernel so a profile entry can
  name a wasm artifact; the harness can drive mixed profiles (native-harness +
  wasm entries). Wasm-citing FACADE_GAP cases become executable.

## Acceptance

- Broker: one dispatch path proven shared by harness lane and wasm lane (call
  traces/ledger events show the same choke point); grant refusal and ledger
  append behaviorally pinned.
- Hosting: fixture component loads by hash (wrong hash refuses, recorded),
  provides/injects services across the boundary, registers effects whose undos
  replay on dispose; instance drop leaves no trace (I1 through the boundary).
- Hot-swap: healthy swap replaces atomically with old-warm-until-healthy;
  failing swap auto-rolls back with both phases ledger-recorded; artifact-hash
  batching proven with two entries sharing one artifact.
- Harness-lane closure: production feature build contains no in-proc plugin
  lane (compile-gate proven); WIT files pass `wit-bindgen`/wasmtime validation.
- Containment: a trapping guest and a spinning guest each deactivate only their
  fiber; siblings unaffected; recorded errors attributed.
- New verifier-validated greens with catalog + expected-green verifier-owned;
  check-ratchet.sh green; remaining reds at designed sites with recorded
  reasons (expected: demo-assembly-only cases).
- Gates: fmt, clippy -D warnings, build, test, ratchet — real tails; loom where
  interleaving-sensitive (swap machine); miri on touched non-FFI crates
  (wasmtime exclusions listed).
- LOC within ceilings; files under 300 lines; two-key: zero implementer touches
  under tests/invariants/.
