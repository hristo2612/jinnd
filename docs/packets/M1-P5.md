## Scope

### `crates/jinnd-events`
- **Typed events with a declared dispatch mode** (R3): each event type states
  its payload type and its mode at the type level.
- **Five dispatch modes** (LAW §3): `emit` (notify all, results ignored),
  `parallel` (concurrent, results gathered), `serial` (sequential in
  registration order), `bail` (first decisive result stops the walk),
  `waterfall` (each listener transforms the accumulated value in order).
- **Inverted routing**: the emitted payload's filter selects listeners by
  interrogating each listener's context (isolation-aware via `jinnd-context`) —
  the listener never filters the payload.
- **Listener registration is just an effect** (R5): registering returns through
  the effects engine; the undo removes the listener. No ad-hoc listener maps
  mutated outside the primitive.
- **R9 hazards stay dead, mechanically**: an erroring/panicking listener NEVER
  aborts the remaining listeners in emit/parallel/serial (each listener is
  panic-contained per R11 and its outcome recorded); an async result pending is
  NEVER treated as "bailed" — bail requires a decisive value.
- **Async-first** (R1): dispatch is async; no lock is held across a listener
  call; listener sets are snapshotted before the walk so registration during
  dispatch cannot deadlock or invalidate the iteration.

### `crates/jinnd-adapter` wiring
- Wire the events subsystem over the bus + existing crates. The 14
  `NO_KERNEL: events` cases become executable; loader keeps its exact `todo!`
  reason strings.
- Reason transitions follow the adjudicated protocol (M1-P4 rulings): every red
  fails at a designed site with its recorded reason; the verifier owns the
  per-case catalog and `expected-green.txt` updates on the branch.
