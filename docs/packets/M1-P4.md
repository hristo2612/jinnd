## Scope

### `crates/jinnd-registry`
- Typed service slots keyed by the context crate's `ServiceKey` (R3); resolution
  honors context isolation boundaries (realm lookup via `jinnd-context`).
- Registration/provision are **effects** on the owning fiber's scope (R5) — a
  provider's slot disappears through undo replay, never through ad-hoc mutation.
- **Reactive availability** via `watch` (never polled, R1), implementing the
  readiness trait `jinnd-fiber` abstracted in P3: a consumer fiber activates only
  when every injected provider is Active and passes its check.
- **Epoch gating**: a consumer's epoch encodes the generation/uid of every
  injected provider. Any provider change — including hot-swap — changes the
  epoch and forces the consumer through a full clean unload → reload. There is
  no silent replace, ever (R9).
- **Provider-waits-for-consumers disposal** (I2 semantics): a dying provider
  unregisters its slot and notifies first, then awaits all dependents' unload
  completion before its value drops — dependents may still call the dying
  service during their own teardown.

### `crates/jinnd-adapter` wiring
- Implement `kernel()` over context + effects + fiber + registry: spawn / update /
  restart / wait_for_quiescence / state and the service provide/inject paths.
- Wire ONLY subsystems that exist. Events/loader/etc. keep their `todo!` stubs
  with their **exact current reason strings**. If any red case's failure reason
  would change without the case going green, STOP and report — the verifier
  rules; the ratchet enforces original reasons.
