## Scope

### #19 → `contracts/jinn-introspect` 0.1.0 (read-only)
- `entries() → list<entry>` with `{ id, fiber, state, incarnation,
  provisions, registrations { listeners, alarms, sockets, processes } }`;
  `readiness() → { boot-reconciled, watcher-armed }`. Granted like any
  contract (a plugin sees the composition only when its profile entry says
  so); every read is a ledgered contract call; reads never block across
  guest delivery (R1 — snapshot from kernel-owned state).
- Ledger fidelity fixes riding with it (Law 2): the ledger's `entry` column
  is filled for every attributable event (fiber → entry mapping is
  kernel-known); `GrantRefused` carries the typed refusal reason.

### #20 → live `jinn:ledger` provider behind its existing bundle
- Register the reader in the daemon like the other base providers:
  `read-range(from-id, limit)` paged, `last-seq()`; consumption receipts
  per constitution 02, the reader's own receipts excluded from its feed;
  payloads redacted by the bundle's declared sensitivity class. Read-only;
  granted; ledgered per read (the receipt IS the record).

### #21 → `contracts/jinn-profile` 0.1.0 — profile patch as operator intent
- `patch-entry(id, merge-patch) → applied | refused(reason)`: applied BY THE
  LOADER (not by a guest's fs write) — validated against the profile
  schema, written back atomically (stage + fsync + rename), and RECORDED as
  a typed `ProfilePatched { entry, by }` ledger event with **no fs inverse
  and no fiber journal entry**: the profile's history is the ledger's, not
  a fiber's contribution. Disposing the editing plugin never touches the
  document. The daemon's own-write recognition (K5) treats the write-back as
  its own. This retires the profile case of #22 and the data-root coupling
  the harness had to adopt.
- Granted per entry (an editor entry holds a `jinn:profile` grant; scope =
  which entry ids it may patch, fail-closed per the K2 law; `*` allowed only
  when declared).

### #23 → readiness wake for kernel-registered sockets (`jinn:net` edition)
- The kernel delivers `lifecycle.handle-event(token, "jinn:net/readable",
  handle)` when a listener has a pending connection or a connection has
  bytes/EOF — a server holds NO alarm. One wake per readiness transition
  (level-triggered, coalesced; never a wake per byte — R9). Wakes are
  ledgered like `AlarmWake`. `accept`/`read` stay non-blocking; the guest
  that ignores wakes and polls still works. Additive edition of the
  `jinn-net` bundle (R12); world stays 0.4.0 if additive, else 0.5.0 with
  contracts mirrored (the round-4 K6 law: typed on the wire, world mirrors
  contracts).

## Round protocol
Standard kernel-packet rounds; verifier owns invariant additions
(candidates: introspection-is-read-only-and-ledgered; profile-patch-has-no-
inverse-and-survives-editor-dispose; readable-wake-coalesced;

outside the grant scope; patch that fails schema validation must refuse
without partial write; readiness storm under a chatty peer stays bounded.

## Acceptance
- Fixture through the real daemon: introspect lists the fixture's own entry
  with correct state/incarnation/registrations and readiness; ledger
  read-range pages with receipts and redaction; `patch-entry` restarts
  exactly the patched fiber (uid evidence) and DISPOSING THE EDITOR LEAVES
  THE DOCUMENT UNCHANGED (the harness transcript `disposing_the_editor_
  reverts_the_operators_edit_finding_21` flips red on adoption); a listener
  receives `jinn:net/readable` on connect and on data with zero alarms held,
  wake count bounded under a flood.
- Ratchet: no regressions (95/35; growth only via verifier adjudication);
  gates + loom (readiness/suspend interleavings) + miri (non-FFI) +
  `--locked`; two-key clean; ceilings per this card; src files under the
  300-line cap (over-cap files touched owe their split).
- Harness adopts via pin-bump 6 (retires `kernel.unavailable` fields for
  #19/#20, the fs-based edit lane for #21, the alarm poll loop for #23; the
  API then qualifies for the soak profile).
