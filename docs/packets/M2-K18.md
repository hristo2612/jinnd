# M2-K18 — the canonical LOC meter is wrong in two ways: it cannot see a dirty tree, and it bills required contract prose as production code

**Milestone:** M2 — instrument packet (the declared-budget process depends on
this meter and it has produced five false or unenforceable readings) ·
**Owner:** kernel-dev · **Status:** ready · **Todo:** PLA-338 · **Binding
rules:** R10, Laws 1/2 · **Design decisions in scope: ONE** — what the meter
counts and when it refuses · **Facade:** NO `jinnd-api` delta · **Size:**
declare a budget with its meter, before code; the script itself lives under
`tools/` and is metered on its own line, production meter 0 · **Standing
gates:** all usual + `cargo build --workspace --locked`.

## The defects, by instance

The meter quoted in cards since M2-K3 (`git diff --numstat main...HEAD --
<surfaces> | awk 'index($3,"tests.rs")==0 ...'`) is load-bearing: since
2026-09-01 the implementer's DECLARED budget replaced the COO's guessed
ceiling, and a meter that reports confidently wrong numbers corrupts the
process that depends on it.

1. **It cannot see a dirty tree.** `git diff main...HEAD` ignores untracked
   files. Mid-round M2-K14 measured 929 against a declared 950 while
   `admit.rs` (+124) was untracked; the real figure was 1065. Nothing in the
   output said the number was incomplete.
2. **It bills required prose at the code rate.** Bundle directories are
   named, so every `.md` counts, while the same card demands stated reasons
   in the contract of record — a standing incentive to under-document the
   file the project calls "the product".
3. **It decides cfg(test)-ness by filename and misses the category.** Five
   instances in two days: a `crates/*/src/*.rs` glob that dropped top-level
   files (K15 r1); `tests/` directories under `src/` (K15 r3); a
   `#[cfg(test)] mod` registration in a parent file (K20 — a false Blocker on
   a zero-production packet); mandated doc/precondition lines (K21); a
   ruling-mandated overrun read as an overrun (K16 r2). Each cost a round.

## What to build — one script, compiler-derived, refusing when it cannot know

1. **One canonical meter script in the repo** (`tools/loc-meter` or the name
   you justify), cited by path from cards from now on. A command quoted in
   ten cards is the two-hand-maintained-copies class M2-K16 just killed; it
   had already drifted.
2. **cfg(test)-ness is decided the way the compiler decides it**, not by
   filename: ask cargo which sources the non-test build compiles (e.g. a
   `cargo build`/`check` dep-info pass, `--message-format=json`, or `cargo
   metadata` plus a `#[cfg(test)]` module walk — you choose and justify under
   R10). A `#[cfg(test)]` attribute and the `mod` it governs, `*_tests.rs`
   siblings, `tests.rs`, `tests/` directories under `src/`, and crate-level
   `tests/` are all outside production by construction, not by pattern.
3. **Refuse on a dirty tree.** Uncommitted or untracked files inside the
   metered surfaces → the meter exits non-zero naming them; it never prints a
   number it knows is incomplete. (Refusing beats a caveat: a number nobody
   can misread beats a number with a footnote.)
4. **Prose: exclude Markdown from the production meter** and report it on a
   separate line with its own count — decide this or "separate budget", say
   why, do only one. Contract files (`.wit`, `.toml`) are reported on their
   own line too; facade (`crates/jinnd-api`) on its own line. One invocation,
   four labelled lines: production / facade / contracts / prose.
5. **Required test cases** (a fixture repo or a temp git tree; red-first for
   each): a `#[cfg(test)] mod` registration in a production file counts 0; a
   `tests/` dir under `src/` counts 0; a `*_tests.rs` sibling counts 0;
   `contracts/**/README.md` lands on the prose line; an untracked file in a
   metered surface makes the meter REFUSE; a clean tree reproduces a known
   historical number.
6. **Re-measure the M2-K14 branch** (`packet/m2-k14-outbound-authority` at
   `de43d06`) with the script and report old vs new figures; if prose
   exclusion changes it materially, say by how much.
7. **Update at least one card to cite the script by path** (M2-K21 or this
   one) as the pattern; do NOT rewrite historical cards' recorded numbers.

verdict and fixed before land. An overrun made solely of ruling-mandated
lines is MANDATED, not a Blocker (kernel-packet rev 11). The repo is PUBLIC:
zero personal data or machine paths in any push.

THREAT MODEL: honest mis-measurement under ordinary use. Not an adversary

## COO rulings — 2026-09-02, after round 1 (binding; round 2 is the LAST round)

Round 1 delivered the instrument: `tools/loc-meter` with compiler-derived
cfg(test) (proven equal to cargo's dep-info), dirty-tree refusal, four
labelled lines, 15 red-first cases, four mutations in form, the K14 branch
re-measured (old 1101 = production 865 + contracts 161 + prose 65 + 10
cfg-off), two cards and AGENTS.md citing the script. The verifier's own
fixtures found two real defects; ruled with the budget item:

1. **Cross-category rename accounting — UPHELD (Blocker).** A rename whose
   old and new paths fall in different categories must be accounted as a
   full DELETE on the old line and a full ADD on the new line; only a rename
   within one category is diffed as content. The verifier's fixture (an
   unchanged `tools/extra.rs` moved to `crates/alpha/src/extra.rs`; legacy
   readings crates +5 / tools −3) is the red-first case, verbatim.
2. **Silent catch in the module walk — UPHELD (Major, behaviour).** A
   `mod` the walk cannot read is a compiler error, and the meter's claim is
   "the compiler's view"; returning `Ok(())` there presents an incomplete
   view as a number. The meter REFUSES (non-zero, naming the unresolved
   module) — the same rule as the dirty tree. Red-first: a committed
   `mod absent;` makes the meter exit non-zero before it makes `cargo check`
   fail.
3. **Tools line 1577 vs a self-declared ≤ 1300 — NOT a Blocker; the
   number is void.** This card set NO ceiling on the tools line on purpose
   ("metered on its own line"), and the declaration itself said "capped by
   nothing on the card, declared here so it is checkable". A self-declared
   estimate with no card ceiling is an estimate: missing it is reported with
   its breakdown, never adjudicated. What binds instead, all held at
   `2b20a73`: every file ≤ 300 lines, tool-only (never a kernel dependency),
   zero new packages, production 0, facade 0. Round 2's additions for items
   1 and 2 are reported on the tools line with no ceiling.

**Round 2, exhaustively:** items 1 and 2 with their red-first cases and one
