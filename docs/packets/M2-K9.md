## Why now

K8 made `jinn:profile.patch-entry` non-blocking: it answers once the
document is committed and the patched fiber's restart is SCHEDULED. That is
correct and it removed a deadlock — but it created an observable window in
which a fiber has a pending restart and is still addressable. A serial
dispatch landing in that window is delivered to an incarnation the loader is
already replacing, and it waits for a peer that will never answer. Today the
kernel offers **no refusal, no ledger row, and no way to ask** — the caller
simply stalls to the guest deadline.

The harness hit this for real: the settings provider's `changed` notice
stalled `PATCH /v1/settings/cron` forever. The harness's only available
workaround is for a provider to *know which layer it wrote* and pick a
dispatch mode accordingly — knowledge it should not need and, per the
round-2 verify, does not reliably have. That is exactly the shape the
two-way rule says becomes a kernel card rather than a harness workaround.

## Scope

### The refusal
- A serial (reply-expecting) dispatch whose target fiber has a pending
  restart REFUSES immediately with a typed `Restarting` reason carrying the
  target's identity and the incarnation being replaced. It never blocks, and
  it never silently lands in the doomed incarnation.
- Fire-and-forget dispatch is unaffected in delivery semantics; state
  whether it is dropped or delivered, and prove whichever you choose.
- Red-first: reproduce the harness's two-hop shape (patch an entry, then
  serially dispatch to it before the swap commits) and assert the typed
  refusal instead of a deadline stall.

### Observability (Law 2)
- The refusal is a ledgered row like any other refusal — a caller reading
  the ledger can tell a `Restarting` refusal from a scope refusal.
- `jinn:introspect` exposes the pending-restart state so a caller can ASK
  rather than discover by stalling. Additive per R12.

### Caller guidance
- Document the contract: on `Restarting`, the caller retries after the
  restart completes (observable via the ledger's fiber transition or
  introspect). The kernel does NOT queue the dispatch across the swap —
  queuing hides a real state transition behind unbounded buffering; the
  refusal is the honest, fail-closed answer.

## Round protocol
