# Packet M1-P2 — Reversible Effects (`jinnd-effects`)

**Milestone:** M1 · **Owner:** kernel-dev · **Status:** ready ·
**Binding rules:** R1, R3, R5, R9, R10, R11 · **LOC budget:** 300–400 (SOURCE-OF-TRUTH §6).

## Scope

Implement `crates/jinnd-effects`: the reversible-effect engine — the kernel's single
mutation primitive (R5). Pre-fiber: this crate is the standalone effect/undo engine;
fibers adopt it in the next packet.

- Effect record: label + undo disposer + children, forming the **live effect tree**
  (R5: the tree is free introspection — a scope can enumerate its live effects with
  labels). Child registration nests structurally, so disposing a parent replays its
  whole subtree.
- Disposer forms per the audit doc (cordis `ctx.effect()`): sync fn, async (boxed
  future), and stepwise (an ordered sequence of undo steps with a cooperative
  cancellation point between steps — epoch-checked cancellation semantics arrive
  with the fiber engine; here the seam is a plain cancellation token).
- Teardown replay: strict LIFO within a scope, subtree-cascading, each undo runs
  **exactly once**. A panicking or erroring undo is caught (R11), recorded, and the
  remaining undos still run — never abort-on-first-error (R9). Replay returns a
  per-effect outcome report (the future ledger feed, R6 — no ledger in this packet).
- Async-first (R1): replay is async, tokio-native; no `block_on`, no lock held
  across an undo call.
- Typed surface (R3): labels/ids as newtypes or `&'static str`; no stringly control
  flow, no `Arc<dyn Any>` API surface.
