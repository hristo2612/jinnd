# Packet M1-P1 — Context Tree (`jinnd-context`)

**Milestone:** M1 · **Owner:** kernel-dev · **Status:** ready ·
**Binding rules:** R3, R4, R5, R10, R11 · **LOC budget:** 500–700 (SOURCE-OF-TRUTH §6).

## Scope

Implement `crates/jinnd-context`: the context type behind the `jinnd-api` facade.

- Context as a cheap cloneable handle (Arc innards); O(1) child derivation.
- Parent-pointer chains for the isolation map (service key → realm id) and the
  intercept chain (per-subtree config overlays). Frozen layers: a derived layer
  adds own keys at derivation time only (audit doc: cordis never mutates ancestor
  layers post-derivation — do not build live-mutation machinery).
- Realm ids as newtype u64 (R3). No strings in the hot path; string lane only via
  the facade's dynamic-key type.
- Typed service-key resolution walk with isolation-boundary stop semantics
  (facade contract; see cordis reflect.ts:80-94 semantics in the audit doc).
- NO service storage, NO fibers, NO events — those are later packets. This crate
  is pure tree/lookup structure (R10: smallest thing that satisfies its tests).
